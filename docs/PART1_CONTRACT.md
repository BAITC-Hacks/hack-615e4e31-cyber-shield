# Контракт первой части

> Исторический контракт первой части. Текущие расширения описаны в [PROPOSALS.md](PROPOSALS.md), [QUALITY.md](QUALITY.md) и [README](../README.md): отклики и ручной выбор уже реализованы, рейтинг учитывает проверку содержания.

Реализуем локальное веб-приложение: React/TypeScript, FastAPI/Python, SQLite. Предоставляются тестовые роли без настоящей регистрации и аутентификации. Не разворачиваем сайт: отправка в GitHub разрешена отдельно. В этой части есть создание/редактирование/подтверждение/публикация задач, рейтинг, общий каталог и рекомендации-квесты по навыкам. Сохранение квеста — интерес студента, не назначение исполнителя. AI-уточнение и сборка неподтверждённой карточки включены. Полноценная отправка откликов и выбор команды — следующие этапы.

Форма данных фронтенда зафиксирована в `frontend/lib/contracts.ts`. JSON сохраняет camelCase. Типы `TaskFields`, `TaskInput`, `Task`, `Rating`, `StudentProfile`, `Quest` являются общим контрактом.

## API

Базовый путь `/api`. Сервер слушает только `127.0.0.1:8000`. CORS разрешает `http://localhost:5173` и `http://127.0.0.1:5173`. Заголовок `X-Demo-Role: business` требуется для операций бизнеса. Это только проверка тестовой роли, не настоящая авторизация. Идентификатор владельца фиксирован: `business-demo`.

- `GET /api/health` → `{status:"ok", stage:1}`.
- `GET /api/tasks` → `Task[]` опубликованные снимки, сортировка по rating.score по убыванию. Запрос поддерживает `topic`, `readiness`, `q`.
- `GET /api/tasks?view=business` → `Task[]` актуальные черновики всех задач тестового бизнеса, нужен бизнес-заголовок.
- `GET /api/tasks/{id}` → опубликованный Task; `?view=business` → актуальный черновик.
- `POST /api/tasks` с `TaskInput` → созданный Task, HTTP 201. Сохраняется неподтверждённый черновик.
- `PUT /api/tasks/{id}` с `TaskInput` → обновлённый Task. Изменение сбрасывает подтверждение, повышает ревизию, но не изменяет опубликованный снимок.
- `POST /api/tasks/{id}/confirm` без тела → Task с подтверждёнными текущими полями.
- `POST /api/tasks/{id}/publish` без тела → Task. Нужна подтверждённая текущая ревизия и непустое название. Публикуется снимок. Нет минимального рейтинга.
- `POST /api/rating/preview` с `{fields:TaskFields}` → Rating предполагаемой заполненности. Подтверждение не меняет.
- `GET /api/profiles` → StudentProfile[] (5 синтетических профилей).
- `PUT /api/profiles/{id}/skills` с `{skills:string[]}` → StudentProfile. Нужен `X-Demo-Role: student`.
- `GET /api/quests?profileId=...` → Quest[]: только опубликованные задачи от 40 баллов, при заданных requiredSkills все требуемые навыки есть в профиле (сравнение без регистра). Если requiredSkills пуст, допускается точное совпадение интереса с topic/industry; matchedInterests явно объясняет причину. Отклонённые и сохранённые рекомендации не показываются повторно. На выдаче максимум 3.
- `POST /api/quests/{taskId}/decision` с `{profileId:string, decision:"saved"|"dismissed"}` → `{ok:true}`. Нужен student-заголовок; задача должна быть опубликована. Решение не назначает исполнителя.
- `GET /api/saved?profileId=...` → Task[] сохранённые опубликованные задачи профиля, включая задачи ниже 40, если студент сохранил их из общего каталога.

Ошибки возвращаются с подходящим HTTP-статусом и полем `detail`. Чтение чужой/несуществующей задачи не возвращает чужой черновик. Вход валидируется, SQL параметризован, тексты не интерпретируются как код или HTML. Локальная SQLite-база в `backend/data/`, путь может задаваться `APP_DB_PATH`. Первый запуск добавляет 5 опубликованных карточек разных уровней, 5 неопубликованных черновиков и 5 профилей. Приложение не удаляет данные на обычном запуске.

## Рейтинг

Контекст 10 + потребность 10; данные 20; ожидаемый результат 15; критерии успеха 15; ограничения 10; пользователи 10; контакт 5 + консультации и обратная связь 5. Дополнительное feedbackProcess сохраняется как необязательное уточнение без отдельного веса. Итого 100.

Пустой текст и явные заглушки «уточнить», «неизвестно», «TBD», «...» баллов не дают. Рейтинг текущего черновика начисляется только после подтверждения; до этого rating.score=0, а previewRating показывает потенциальный результат. Опубликованный снимок имеет собственное подтверждение и рейтинг. Наличие содержательного текста не доказывает фактическую достоверность: интерфейс называет это готовностью описания.

## Набор данных и происхождение

`fixtures/hackalem_synthetic_data.json` и `fixtures/README_hackalem.md` — неизменённые исходники пользователя. При первом старте импортируются 5 опубликованных карточек с рейтингами 20, 50, 75, 90, 100 и 5 исходных черновиков. Все 20 исходных записей, включая 5 команд и 5 откликов, хранятся в `fixture_records`.

`GET /api/demo-data` возвращает исходный набор и плоскую карту `apiIds` из ID карточек/черновиков в стабильные UUID API. Это просмотр исходных примеров; отправка и выбор реальных откликов ещё не реализованы.

Task содержит дополнительные read-only поля `sourceId`, `sourceDraftId`, `industry`, `confirmedFields`. При импорте начисляются только баллы из `confirmed_fields`; `null` не даёт баллов. При редактировании подтверждение всей текущей версии сбрасывается, а после явного подтверждения человек подтверждает все текущие поля. Опубликованный снимок остаётся независимым.

## AI-помощник

Оба запроса требуют `X-Demo-Role: business` и не изменяют SQLite.

- `POST /api/ai/analyze`: `{description, fields?}` → `{mode, missingFields, questions:[{id,field,question}], warnings, promptVersion}`.
- `POST /api/ai/build-card`: `{description, fields?, answers:[{field,answer}]}` → `{mode, fields, sources:{field:[{sourceId,quote}]}, confirmed:false, warnings, promptVersion}`.

`mode` равен `openai` либо `local_stub`. Внешний ответ проверяется по схеме и точным исходным цитатам. При ошибке или отсутствии ключа возвращается явно обозначенная локальная заглушка. Полный промпт, примеры и ограничения: [AI.md](AI.md).

## Компоненты интерфейса

`TaskEditor` — форма из четырёх шагов с предварительным рейтингом, AI-помощником и отдельным подтверждением перед публикацией. `AIAssistant` показывает вопросы и проект карточки с источниками; перенос выполняется явной кнопкой и сбрасывает подтверждение. Если пользователь изменил форму во время запроса, результат нельзя применить к другой версии.

`TaskDetails` — окно со всеми полями и разбивкой рейтинга. Низкий рейтинг не блокирует открытие или сохранение задачи. `RatingPanel` показывает рассчитанный сервером результат. Общий API-клиент — `frontend/lib/api.ts`, типы — `frontend/lib/contracts.ts`.

Цвета интерфейса: #5b6bc4, #1a2250, #f7f8fc. Тестовые роли не являются аутентификацией; сохранение квеста не является откликом или назначением.

# Запуск Alem / HackAlem MVP

Это подробная самостоятельная инструкция для разработчика и проверяющего. Если нужно только открыть MVP, начните с [простой инструкции](QUICKSTART.md). Приложение запускается на одном компьютере: Next.js показывает интерфейс, FastAPI выполняет операции, SQLite хранит данные. Внешний AI подключается отдельно; для первого запуска API-ключ не нужен.

Все команды ниже выполняются в терминале **из корня проекта** — папки, где находятся `README.md`, `backend`, `frontend` и `scripts`. Команды рассчитаны на bash/zsh в macOS/Linux.

## 1. Требования

| Инструмент | Требование и назначение |
| --- | --- |
| Git | Получение исходников из репозитория; при распаковке готового архива не обязателен |
| Python | **3.11 или новее**, с модулями `venv` и `pip` для создания окружения backend |
| Node.js | **22.13.0 или новее** |
| npm | Должен быть доступен в `PATH` вместе с Node.js |
| Браузер | Для открытия локального веб-приложения |
| Интернет | Для клонирования, первоначальной установки зависимостей и необязательных запросов внешнему AI |
| Свободные порты | `127.0.0.1:8000` для FastAPI и `127.0.0.1:5173` для Next.js |

Зафиксированное проверенное окружение проекта: **macOS, Python 3.13.9, Node.js 25.8.0**. Общий скрипт содержит поддержку POSIX и рассчитан на macOS/Linux; отдельный полный прогон на Linux этим руководством не заявляется. Windows не проверен: `scripts/dev.py` отклоняет запуск на этой ОС, а пути и команды в этом документе предназначены для macOS/Linux.

Версии Python-пакетов закреплены в [backend/requirements.txt](../backend/requirements.txt), зависимости frontend — в [frontend/package-lock.json](../frontend/package-lock.json). Устанавливать PostgreSQL, Docker или отдельный сервер базы данных не требуется.

## 2. Получение проекта в папку Hakaton

Выберите папку для проектов. Например:

```sh
mkdir -p "$HOME/Projects"
cd "$HOME/Projects"
git clone https://github.com/BAITC-Hacks/hack-615e4e31-cyber-shield.git Hakaton
cd Hakaton
```

Если `Hakaton` уже существует и содержит проект, просто откройте её в терминале; не клонируйте репозиторий поверх имеющихся файлов. Название папки не влияет на работу приложения. Для архива распакуйте исходники в `Hakaton` и перейдите в каталог с `scripts/setup.py`.

При ошибке доступа GitHub проверьте URL и доступ своей учётной записи к репозиторию. Токены и пароли не нужно включать в адрес клонирования или файлы проекта.

Перед установкой можно проверить инструменты:

```sh
git --version
python3 --version
node --version
npm --version
python3 scripts/setup.py --check
```

`setup.py --check` проверяет версии Python/Node, наличие npm и файлов зависимостей. Он **не устанавливает пакеты** и не доказывает, что сервер уже можно запустить. Успешный результат заканчивается сообщением `Предварительная проверка пройдена. Зависимости не изменены.`

## 3. Установка зависимостей

```sh
python3 scripts/setup.py
```

Скрипт выполняет следующие действия:

1. Проверяет инструменты и версии.
2. Создаёт `backend/.venv`, если окружение ещё не создано.
3. Устанавливает Python-пакеты из `backend/requirements.txt` и выполняет `pip check`.
4. В папке `frontend` запускает `npm ci` по lock-файлу с dev- и optional-зависимостями.

Глобальные Python-пакеты не меняются. Активировать `.venv` вручную не нужно: скрипты используют её Python по точному пути. `npm ci` восстанавливает зависимости frontend по lock-файлу; его не следует выполнять одновременно с работающим Next.js.

Успешная установка завершается строкой `Готово. Запуск: python3 scripts/dev.py`. Если установка прервана или произошла сетевая ошибка, устраните причину и повторите эту же команду. Перед повторной установкой остановите свои сервисы.

## 4. Первый запуск и проверка

```sh
python3 scripts/dev.py --check
python3 scripts/dev.py
```

Первая команда проверяет существующее окружение, импорт основных модулей backend, установленный Next.js и доступность двух портов. Она не запускает серверы. Если приложение уже работает, проверка ожидаемо сообщает о занятых портах; это не повод удалять зависимости или базу.

Вторая команда запускает FastAPI и Next.js и остаётся работать в терминале. Дождитесь `Application startup complete` от backend и `Ready` от Next.js, затем откройте:

| Адрес | Что находится по адресу |
| --- | --- |
| [http://127.0.0.1:5173](http://127.0.0.1:5173) | Веб-приложение |
| [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs) | Swagger UI с маршрутами API |
| [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health) | Проверка FastAPI; ожидается JSON со `status: "ok"` |
| [http://127.0.0.1:5173/api/health](http://127.0.0.1:5173/api/health) | Та же проверка через прокси Next.js |

При наличии `curl` можно проверить оба пути из второго терминала:

```sh
curl --fail http://127.0.0.1:8000/api/health
curl --fail http://127.0.0.1:5173/api/health
```

Один успешный health-запрос проверяет доступность маршрута, а не весь пользовательский сценарий. Для проверки интерфейса переключите тестовые роли, откройте карточку задачи и раздел откликов.

На новой базе появляются пять опубликованных карточек, пять неопубликованных черновиков, пять индивидуальных профилей, пять команд и пять откликов на рассмотрении. Исходные рейтинги карточек: **20, 50, 75, 90 и 100**. В каталоге они сортируются по убыванию баллов. Команды начинают с нулевого баланса; награда появляется после отдельного ручного подтверждения завершения бизнесом.

Все серверы слушают `127.0.0.1`: показ доступен на этом компьютере. Это локальный запуск, а не публикация сайта в интернете.

## 5. Остановка и повторный запуск

Для остановки нажмите **Ctrl-C в терминале общего запуска**. Скрипт останавливает оба запущенных им сервиса и их дочерние процессы. Код завершения `130` после Ctrl-C ожидаем. Если один из сервисов аварийно завершится, общий скрипт остановит второй; причина будет видна в том же терминале.

Для следующего запуска:

```sh
cd "$HOME/Projects/Hakaton"
python3 scripts/dev.py
```

Измените путь `cd`, если выбрали другую папку. Повторная установка не нужна, пока зависимости не менялись. При том же пути базы сохраняются задачи, опубликованные версии, навыки, квесты, отклики, PDF, решения бизнеса, баллы и оформление комнаты. Примеры не добавляются заново при каждом запуске.

После перезагрузки браузера снова выберите роль, профиль и команду: их текущий выбор хранится в состоянии страницы, а данные — в SQLite.

В режиме разработки Next.js обновляет frontend после изменений. Общий скрипт запускает Uvicorn **без `--reload`**: после правок backend или `.env` остановите и повторите запуск. Для обновления исходников сначала сохраните свою работу и остановите сервисы, затем проверьте `git status` и выполните `git pull --ff-only`. Если Git сообщает о конфликтующих локальных изменениях, не сбрасывайте их. После изменения зависимостей повторите `python3 scripts/setup.py`.

## 6. Запуск двух процессов отдельно

Используйте этот вариант, если нужны отдельные логи frontend/backend. Не запускайте его поверх уже работающего `scripts/dev.py`: используются те же порты.

В первом терминале, из корня проекта:

```sh
backend/.venv/bin/python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Во втором терминале, также из корня:

```sh
npm --prefix frontend run dev
```

Для остановки нажмите Ctrl-C **в каждом терминале**. При отдельном запуске завершение одного сервиса не останавливает другой автоматически.

Frontend передаёт `/api/*` на FastAPI. По умолчанию используется `http://127.0.0.1:8000`. При необходимости явно задать тот же адрес для отдельного запуска:

```sh
BACKEND_URL=http://127.0.0.1:8000 npm --prefix frontend run dev
```

Корневой `.env` загружается кодом FastAPI; Next.js в папке `frontend` не следует считать читателем этого файла. Для настройки frontend передавайте `BACKEND_URL` в окружение его команды. Общий скрипт сам устанавливает `BACKEND_URL=http://127.0.0.1:8000` и использует фиксированные порты 8000/5173.

## 7. Готовая сборка для локального показа

Перед сборкой остановите работающий Next.js. При общем запуске остановите его через Ctrl-C вместе с backend, чтобы процессы не использовали одну папку `frontend/.next` одновременно.

```sh
npm --prefix frontend run build
python3 scripts/dev.py --production --check
python3 scripts/dev.py --production
```

Откройте прежний адрес [127.0.0.1:5173](http://127.0.0.1:5173). Режим `--production` запускает уже собранный frontend через `npm start`; он не собирает проект сам и не развёртывает сайт на внешнем сервере. Backend запускается тем же способом, что и в обычном режиме.

При отдельных процессах запустите FastAPI командой из раздела 6, а frontend — командой:

```sh
npm --prefix frontend run start
```

После правок frontend заново остановите Next.js, выполните `build` и повторите запуск. Если нужен другой `BACKEND_URL`, задайте его **при сборке**: перенаправления входят в результат Next.js. Для стандартного локального адреса дополнительных переменных не требуется.

## 8. Необязательное подключение AI

### Работа без ключа

Для свежего клона можно пропустить создание `.env`: приложение работает без внешнего API. В этом режиме помощник предлагает локальные уточняющие вопросы и неподтверждённую карточку, рейтинг рассчитывается правилами. Внешняя проверка смысла недоступна. Кнопка «Расписать подробнее с ИИ» честно возвращает исходное описание в резервном режиме; оно не выдаётся за переписанный моделью текст.

Чтобы явно отключить внешние вызовы для одного запуска, даже если ключ уже есть в `.env` или окружении терминала:

```sh
ALEM_LOAD_ENV=0 OPENAI_API_KEY= python3 scripts/dev.py
```

`ALEM_LOAD_ENV=0` отключает загрузку корневого `.env`, а пустой `OPENAI_API_KEY=` перекрывает унаследованный ключ для этой команды. При таком запуске настройки базы из `.env` тоже не читаются; для сохранения нужного пути передайте `APP_DB_PATH` явно, как в разделе 9.

Безопасная проверка режима без обращения к провайдеру:

```sh
ALEM_LOAD_ENV=0 OPENAI_API_KEY= backend/.venv/bin/python scripts/check_ai.py
```

Ожидается сообщение `Ключ не задан...` и **код завершения 1**. В этой проверке это ожидаемый результат, а не ошибка установки MVP.

### Подключение своего ключа

Если корневого `.env` ещё нет, создайте его из шаблона:

```sh
cp -n .env.example .env
```

`-n` сохраняет уже существующий файл. Откройте `.env` в редакторе и заполните значение `OPENAI_API_KEY`. Пример структуры без секрета:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4.1-mini
# Необязательная отдельная модель для смыслового рейтинга:
# OPENAI_RATING_MODEL=gpt-4.1-mini
```

Сохраните файл и перезапустите backend или общий скрипт. Ключ нужен серверу; не добавляйте его в frontend, Git или скриншоты. `.env` исключён из Git. Значения окружения процесса имеют приоритет над `.env`; переменные в значениях `.env` автоматически не подставляются.

Сначала проверьте только наличие настройки:

```sh
backend/.venv/bin/python scripts/check_ai.py
```

При заданном ключе команда показывает выбранную модель, скрывает значение ключа и завершается с кодом 0. **Она не проверяет интернет, действительность ключа, доступ к модели или лимит аккаунта.**

Для одного реального запроса с синтетической карточкой:

```sh
backend/.venv/bin/python scripts/check_ai.py --request
```

Этот шаг обращается к внешнему API и использует его лимит. Успешный ответ проверяется по формату и источникам. Команда проверяет смысловой рейтинг, а не все функции AI сразу; она не подтверждает и не публикует рабочую задачу.

В интерфейсе проверьте нужную функцию отдельно: уточняющие вопросы, сборку карточки, «Проверить смысл с AI» или «Расписать подробнее с ИИ». При расширении описания сначала сравните предложенный вариант с исходником и только затем применяйте его. Формулировка и смысловая оценка могут различаться между запросами; ручная проверка остаётся обязательной.

При заданном ключе подтверждение перед публикацией использует AI. Если провайдер недоступен, публикация этой правки может остановиться: черновик остаётся сохранённым, прежняя опубликованная версия сохраняется. Помощник и расширение описания при некоторых ошибках переходят в явно обозначенный резервный режим. Эти режимы нельзя смешивать при оценке успешности подключения.

Подробнее: [AI-конструктор](AI.md), [смысловой рейтинг](SEMANTIC_RATING.md), [расширение описания](DESCRIPTION_EXPANSION.md).

## 9. Отдельная база для тестов и демонстрации

По умолчанию база находится в `backend/data/hackalem.sqlite3`. Для чистого показа не удаляйте её: остановите приложение и выберите **новый, ещё не существующий файл**, например `backend/data/demo-jury-01.sqlite3`. Если такой файл уже есть, используйте другое имя для чистого старта либо тот же файл для продолжения прошлого показа.

Запуск с отдельной базой и воспроизводимым локальным AI-режимом:

```sh
ALEM_LOAD_ENV=0 OPENAI_API_KEY= APP_DB_PATH="$PWD/backend/data/demo-jury-01.sqlite3" python3 scripts/dev.py
```

Для заранее собранного frontend:

```sh
ALEM_LOAD_ENV=0 OPENAI_API_KEY= APP_DB_PATH="$PWD/backend/data/demo-jury-01.sqlite3" python3 scripts/dev.py --production
```

В новой базе автоматически создаются исходные синтетические записи. Рабочая база не изменяется. Чтобы продолжить работу с демонстрационными данными после остановки, повторите команду **с тем же `APP_DB_PATH`**. Чтобы вернуться к обычной базе, остановите демонстрацию и запустите приложение с нужным рабочим путём; стандартная команда использует `APP_DB_PATH` из окружения/`.env`, если он там задан, и только иначе путь по умолчанию.

Абсолютный путь, полученный через `$PWD`, устраняет зависимость относительного `APP_DB_PATH` от рабочей папки. В `.env` указывайте буквальный абсолютный путь, например `/Users/your-name/Projects/Hakaton/backend/data/demo-jury-01.sqlite3`: загрузчик `.env` не раскрывает `$PWD`.

Если нужна копия данных перед экспериментами, сначала остановите приложение, затем скопируйте фактически используемый SQLite-файл в отдельное место. Не копируйте открытую базу как способ гарантированной резервной копии. Файлы `.sqlite3`, зависимости, `.env` и результаты сборки в исходный репозиторий не включаются.

## 10. Автоматические проверки

После установки зависимостей выполните из корня:

```sh
backend/.venv/bin/python -m pytest backend/tests -q
backend/.venv/bin/python -m pip check
npm --prefix frontend run typecheck
npm --prefix frontend run lint
```

Для проверки итоговой сборки остановите Next.js и выполните:

```sh
npm --prefix frontend run build
```

Backend-тесты используют временные базы. Их настройка отключает чтение `.env` и настоящий ключ; внешние ответы имитируются. Эти тесты не требуют платных запросов и не подтверждают доступность реального API. Команда `check_ai.py --request` — отдельная проверка внешнего сервиса.

Актуальные результаты прогонов находятся в [README](../README.md), [проверке наград и рейтинга](STAGE3_VERIFICATION.md), [проверке расширения описания](DESCRIPTION_EXPANSION.md). Точные баллы локальных сценариев README рассчитаны для режима без внешнего ключа. Функциональные проверки включают публикацию, рост рейтинга, отклик команды, ручное решение бизнеса и сохранность после перезапуска. Автотесты и успешная сборка сами по себе не означают, что непрерывное выступление для жюри уже уложилось в пять минут.

## 11. Диагностика

| Симптом | Что проверить и сделать |
| --- | --- |
| `python3`, `node` или `npm` не найден | Установите недостающий инструмент, добавьте его в `PATH`, откройте новый терминал и повторите `python3 scripts/setup.py --check` |
| Версия ниже минимальной | Установите Python 3.11+ или Node.js 22.13.0+; проверяйте именно версии команд `python3`/`node`, видимые в текущем терминале |
| Нет `venv`, `ensurepip` или pip | Установите поддержку виртуальных окружений для своей версии Python; на Linux она может быть отдельным пакетом дистрибутива. Затем повторите установку |
| В существующей `.venv` слишком старый Python | Остановите сервисы, переместите только `backend/.venv` в резервную папку вне репозитория и повторите setup подходящим Python. Папка `backend/data` к окружению не относится |
| Ошибка скачивания pip/npm | Проверьте подключение, доступ к реестрам и настройки прокси. Повторите setup; не заменяйте lock-файл случайным набором версий |
| Ошибка установки `sharp`/`libvips` | Используйте общий setup: он по умолчанию избегает глобального libvips. Если ранее явно задавали `SHARP_FORCE_GLOBAL_LIBVIPS` или сборку из исходников, проверьте эти настройки; скрипт сохраняет явные пользовательские переменные |
| `Порты недоступны` / `Address already in use` | Приложение или другой процесс уже слушает порт. Остановите свой прежний запуск через Ctrl-C либо используйте уже работающий экземпляр. Скрипт не завершает чужие процессы |
| Нет `backend/.venv` / `ModuleNotFoundError` | Повторите `python3 scripts/setup.py`. Backend и тесты запускайте через `backend/.venv/bin/python`, а не случайный системный Python |
| Нет production-сборки / `BUILD_ID` | Сначала остановите Next.js и выполните `npm --prefix frontend run build`, затем запускайте `--production` |

| После запуска «пропали» прошлые задачи | Проверьте, какой `APP_DB_PATH` указан в команде и настройках. Новый файл создаёт новый набор; прежний файл не удаляется автоматически |

# Отклики команд и решения бизнеса

Отклик — самостоятельное предложение решения на опубликованную задачу. Он не связан с сохранением квеста. Низкий рейтинг, отсутствие совпадения навыков или ранее пропущенная рекомендация не мешают отправке предложения. Неопубликованный черновик недоступен для откликов.

## Пользовательский путь

1. Студент открывает задачу и выбирает одну из пяти тестовых команд. Индивидуальный профиль для квестов и команда для отклика выбираются независимо.
2. Студент указывает идею, план по шагам, срок в календарных днях и ссылку на прототип. Допущения и PDF-вложение необязательны. После отправки отклик находится на рассмотрении.
3. В разделе откликов студент видит предложения выбранной команды, статусы и комментарии бизнеса.
4. Бизнес открывает отклики на задачу, сравнивает команды и их предложения и вручную выбирает, отклоняет либо возвращает отклик на рассмотрение.

Можно выбрать ноль, одну или несколько команд. Решение по одному предложению не меняет другие. Срок предложения не запускает календарь и не создаёт автоматических назначений. Личного кабинета с настоящей авторизацией пока нет: роли и команды переключаются в демонстрационном интерфейсе.

После успешной работы бизнес может отдельно подтвердить завершение выбранного проекта и описать принятый результат. Команда получает 100 баллов один раз за задачу; после этого решение по данному отклику фиксируется. Баллы и магазин оформления описаны в [REWARDS.md](REWARDS.md). Простой выбор команды баллов не даёт.

## Контракт API

Все идентификаторы в рабочих API — UUID. Форматы также доступны в Swagger UI запущенного приложения: [API](http://127.0.0.1:8000/docs).

| Запрос | Роль | Результат |
| --- | --- | --- |
| `GET /api/teams` | Любая | Пять тестовых команд с навыками, технологиями и интересами |
| `POST /api/tasks/{taskId}/proposals` | `student` | Создание отклика, HTTP 201 |
| `POST /api/tasks/{taskId}/proposals/upload` | `student` | Отклик с PDF, multipart/form-data, HTTP 201 |
| `GET /api/proposals?teamId={teamId}` | `student` | Все предложения выбранной команды |
| `GET /api/proposals?taskId={taskId}` | `business` | Все предложения на задачу тестового бизнеса |
| `PUT /api/proposals/{proposalId}/decision` | `business` | Обновлённый отклик с ручным решением |
| `GET /api/proposals/{proposalId}/attachments/{attachmentId}` | `business` либо `student` с `teamId` | Скачивание PDF владельцем задачи или отправившей командой |

Роль передаётся заголовком `X-Demo-Role`. Для списка откликов нужен ровно один фильтр: `teamId` или `taskId`. Клиент не может передать статус выбора при создании предложения. Система не ограничивает количество предложений, в том числе от одной команды на одну задачу.

Пример тела отправки (замените `teamId` на значение из `GET /api/teams`):

```json
{
  "teamId": "00000000-0000-0000-0000-000000000001",
  "idea": "Собрать список заказов с поиском и фильтрами.",
  "plan": [
    "Уточнить формат тестовой таблицы и условия приёмки",
    "Сделать прототип списка и импорт",
    "Проверить результат на синтетических заказах"
  ],
  "durationDays": 7,
  "prototypeUrl": "https://example.com/orders-demo",
  "assumptions": ["Работаем только с синтетическими данными"]
}
```

Идея обязательна и ограничена 6000 символами; план содержит 1–20 непустых шагов; срок — целое число 1–365. Для ссылки разрешены только HTTP и HTTPS, до 2048 символов. Допущений — до 20. Неизвестные поля запрещены. Сервер не скачивает содержимое ссылки, не проверяет существование прототипа и не выполняет текст предложения как код.

Ответ содержит `id`, `sourceId` для импортированной записи, `taskId`, `taskTitle`, `teamId`, объект `team`, поля предложения, `prototypeIsPlaceholder`, `status`, `decisionComment`, `createdAt`, `updatedAt` и `attachments`. Новый отклик имеет `status: "submitted"`; без файла `attachments: []`.

## PDF-вложение

В `/proposals/upload` передаются ровно две части multipart: `proposal` — JSON-строка объекта из примера выше, `file` — один PDF до **10 × 1024 × 1024 байт**. Без файла используется обычный JSON-маршрут. Поля предложения и ссылка остаются обязательными; файл дополняет их.

Сервер ограничивает весь входящий поток до 10,5 МиБ до разбора multipart; допустимый JSON занимает не больше 256 КиБ. В Next.js `experimental.proxyClientMaxBodySize` установлен в 11 МиБ, чтобы PDF с multipart-обвязкой дошёл до backend. Используется [python-multipart](https://pypi.org/project/python-multipart/) по механизму [FastAPI Forms and Files](https://fastapi.tiangolo.com/tutorial/request-forms-and-files/).

Проверяются расширение `.pdf`, длина имени, тип содержимого, сигнатура `%PDF-` и маркер завершения `%%EOF`. Части пути и управляющие символы удаляются из имени. Это базовая проверка формата, а не полноценный разбор PDF или антивирус. Приложение не исполняет, не индексирует и не отправляет содержимое документа в AI.

Метаданные `attachments` содержат `id`, `name`, `size`, `mediaType: "application/pdf"` и `createdAt`. PDF хранится в таблице `proposal_attachments` как BLOB, в одной транзакции с откликом. Если файл или поля не прошли проверку, не создаётся ни отклик, ни файл. Сохранённые вложения переживают перезапуск приложения.

Скачивание требует заголовка роли: бизнес проверяется как владелец задачи, студент передаёт `teamId` отправившей команды. Заголовок роли остаётся демонстрационным, он не заменяет настоящую авторизацию. Файл отдаётся как `Content-Disposition: attachment` с `nosniff` и запретом кэширования, а не как публичный статический ресурс.

Файл [proposal_demo.pdf](../fixtures/proposal_demo.pdf) содержит только синтетический пример для демонстрации. Ошибка размера возвращает HTTP 413, неверный формат — 422, другой тип HTTP-запроса — 415; повреждённый multipart может вернуть 400. В исходных пяти откликах вложений нет: их ссылки-заглушки сохранены.

Пример ручного решения:

```json
{
  "status": "accepted",
  "comment": "Выбираем команду для обсуждения предложенного прототипа."
}
```

Допустимы `submitted` («На рассмотрении»), `accepted` («Выбрана бизнесом») и `rejected` («Отклонена»). Возврат в `submitted` позволяет пересмотреть решение. Комментарий необязателен. Изменение задачи или её рейтинга не меняет статус отклика.

## Данные и ошибки

Пять команд и пять откликов из исходного JSON импортируются в рабочие таблицы с постоянными UUID. Для доставки уже есть два предложения: Route Makers и Simple Flow. Они позволяют показать сравнение без предварительного заполнения форм. Все исходные предложения стартуют на рассмотрении; никто не выбран автоматически.

Ссылки из исходного набора помечены как демонстрационные. Новые ссылки на зарезервированные демонстрационные домены также отмечаются как заглушки. Оригинальные файлы и `/api/demo-data` сохраняют исходные записи даже после решения бизнеса. Обычный перезапуск не дублирует отклики и не сбрасывает их статусы.

Неверный формат возвращает HTTP 422, неподходящая тестовая роль — 403, отсутствующая команда/задача/отклик — 404. Ошибка отображается в форме; при неудачной отправке пользователь может исправить ввод и повторить действие. Кнопки блокируются на время запроса, чтобы избежать повторной отправки двойным нажатием.

Проверки находятся в [test_proposals.py](../backend/tests/test_proposals.py), [test_uploads.py](../backend/tests/test_uploads.py) и [test_workflow.py](../backend/tests/test_workflow.py). Проверяются роли, размер/формат файла, атомарность сохранения, скачивание и перезапуск. Сквозной тест проходит путь от задачи с нулевой оценкой до отклика, ручного выбора, повышения рейтинга и сохранности решения.

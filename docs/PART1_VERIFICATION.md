# Проверка первой части MVP

Первая часть реализует подготовку бизнес-задач с AI-помощником, ручное подтверждение и публикацию, прозрачный рейтинг, общий каталог и рекомендации-квесты по навыкам или интересам. Сохранение рекомендации означает интерес студента; оно не назначает исполнителя.

Состояние на 23 сентября 2026 года: полный backend-прогон завершён — 58 тестов пройдены; актуальные lint, typecheck и production-сборка интерфейса успешны. Основные пользовательские сценарии и локальный AI-режим пройдены координатором в браузере. Совместный production-запуск, остановка через Ctrl-C и повторный запуск проверены. Проверка установки и сборки в отдельной чистой копии описывается ниже отдельно от тестов рабочей папки. Клиент — React 19 / Next.js 16 на `127.0.0.1:5173`, API — Python / FastAPI на `127.0.0.1:8000`, хранение — SQLite. Реализованы каталог, «Мои задачи», «Мои квесты», редактор карточки, просмотр разбивки рейтинга, выбор профиля/навыков и диалог рекомендации.

Предоставленный пользователем набор `fixtures/hackalem_synthetic_data.json` содержит пять опубликованных карточек, пять исходных черновиков, пять профилей команд и пять откликов. Двадцать исходных записей сохранены в `fixture_records`; `/api/demo-data` возвращает справочный набор и карту десяти API-идентификаторов задач/черновиков. Команды и отклики пока доступны только для чтения: отправки, сравнения и решения бизнеса ещё нет. В текущем интерфейсе используются отдельные пять профилей студентов.

Свежая база содержит пять опубликованных оценок **20/50/75/90/100**, пять черновиков и пять студенческих профилей. На существующей базе старые демонстрационные и пользовательские задачи сохраняются, поэтому карточек может быть больше. Исходные записи не выдаются за живые пользовательские решения или работающие прототипы по демонстрационным ссылкам.

## Автоматические проверки

Тесты находятся в `backend/tests/`: интеграционные сценарии используют FastAPI TestClient, AI-адаптер — также httpx.MockTransport. Для тестов состояния pytest создаёт отдельную SQLite-базу во временной папке. Путь передаётся в `create_app(db_path=...)` и `APP_DB_PATH`; рабочая база `backend/data/` не открывается тестами. Повторный запуск приложения проверяется на той же временной базе.

Из корня репозитория после установки зависимостей backend:

```sh
backend/.venv/bin/python -m pytest backend/tests -q
```

Для отдельного прогона проверок API и набора данных:

```sh
backend/.venv/bin/python -m pytest backend/tests/test_part1_api.py backend/tests/test_demo_data.py -q
```

Проверяются реальные HTTP-операции:

- Создание → подтверждение → публикация → чтение после повторного запуска.
- Отказ публикации неподтверждённой версии и карточки без названия.
- Снятие подтверждения при редактировании; публичный снимок не меняется до повторного подтверждения и публикации. После публикации изменённая оценка действительно переставляет задачу относительно другой карточки.
- Оценки 0/100, частичное заполнение, веса разбивки и отсутствие баллов за явные заглушки.
- Доступность, поиск и сохранение опубликованной задачи с нулевой оценкой.
- Ограничение чтения бизнес-черновиков и операций бизнеса тестовой ролью.
- Рекомендации при оценке от 40 и совпадении всех явно требуемых навыков без учёта регистра. Если требований нет, допускается точное совпадение интереса с темой или отраслью; интерес не обходит отсутствующий обязательный навык. Выдаётся максимум три рекомендации.
- Сохранённые и отклонённые рекомендации не предлагаются повторно; решения и навыки профиля переживают повторный запуск и не меняют карточку задачи.
- Неверные типы данных, попытки подставить `confirmed`, `confirmedFields` или `sourceId` при создании, недопустимое решение по квесту, неизвестные объекты и SQL-подобный текст не обходят правила API.
- Начальные данные не дублируются при повторном запуске.
- Исходный JSON соответствует справочному API; 20 записей действительно сохраняются в SQLite, ссылки откликов на команды/задачи целостны и команды из исходного набора не назначены.
- Стабильные UUID5 связаны с исходными идентификаторами. Значения `null` корректно превращаются в пустые поля редактора; исходный текст черновика не дополняется выдуманными данными.
- Оценки импортированных карточек пересчитываются по формуле и совпадают с 20/50/75/90/100; служебные ссылки на источник сохраняются после правки, а справочный JSON от пользовательских изменений не меняется.
- Миграция seed-версии 1 → 2 добавляет набор и сохраняет пользовательскую карточку, навыки и сохранённый квест; повторная инициализация не создаёт дубликаты.

Дополнительно отдельная проверка функции рейтинга подтверждает, что при импорте учитываются только перечисленные подтверждённые поля. Полные 10 баллов за связь с бизнесом теперь состоят из **5 за контакт + 5 за формат консультаций и обратной связи**, как в предоставленном `scoring_policy`. Поле `feedbackProcess` остаётся дополнительным и само не даёт баллов. Это заменяет первоначальную разбивку 4+3+3.

Итоговый прогон координатора 23 сентября 2026 года: **58 passed, 1 warning**, ошибок нет, время **1,33 секунды**. Это 29 проверок API/данных/рейтинга и 29 проверок AI-модуля. Окружение: macOS (Darwin 25.5.0), Python 3.13.9, pytest 9.1.1. Другие операционные системы этим прогоном не проверены.

При запуске есть одно предупреждение зависимости: Starlette сообщает об устаревающем использовании `httpx` внутри TestClient и рекомендует `httpx2`. На текущих закреплённых зависимостях TestClient работает; предупреждение не скрыто и не считается проваленным тестом.

## Проверка AI-модуля

Модуль реализован в репозитории по согласованному контракту; внешний ZIP-модуль не импортировался. Форматы, фактический промпт и ограничения описаны в [AI.md](AI.md).

29 тестов AI проверяют локальный режим, вопросы, сборку карточки, источники, сохранение исходных полей, строгий запрос OpenAI Responses, неверный JSON, недопустимые цитаты и поля, удаление отрицания, отказ модели, тайм-ауты, HTTP-ошибки, ограничения входа и роль. Проверяется отсутствие изменений задач, подтверждения, рейтингов, профилей и решений при AI-запросах.

Тесты внешнего адаптера используют `httpx.MockTransport`, фиктивный ключ и имитацию ответов. **Реальных запросов в OpenAI и платных API-вызовов не было.** Доступность выбранной модели для конкретного аккаунта и качество настоящей внешней генерации не подтверждены. Локальный режим явно обозначен и не выдаётся за живую модель.

AI не сохраняет и не публикует карточку. Предложения с источниками сначала показываются пользователю, затем переносятся в редактор отдельным действием; подтверждение человеком остаётся обязательным. Точное совпадение цитаты не доказывает истинность текста или правильность выбора поля.

## Проверки в браузере

Координатор проверил в работающем локальном приложении:

- Создание и сохранение черновика → ручное подтверждение → публикация карточки с оценкой 20 → появление в общем каталоге.
- Сохранение и пропуск рекомендованного квеста в роли студента.
- Изменение навыков профиля с сохранением значений на сервере.
- Сохранение задачи с низким рейтингом из полной карточки через `TaskDetails`.
- При ширине окна 390 px ширина документа остаётся 390 px; горизонтального переполнения в проверенном состоянии нет. Это не является полной проверкой всех мобильных экранов.

После обновления интерфейса координатор отдельно прошёл локальный AI-сценарий: получил шесть вопросов, ответил о потребности, данных и ожидаемом результате. В предварительной карточке были точные фрагменты-источники, существующее название не изменилось, неизвестные поля остались пустыми. После явного переноса в редактор предварительная оценка стала 55; кнопка публикации оставалась недоступной до отметки подтверждения человеком. Режим `local_stub` был виден пользователю.

Последние `lint`, `typecheck` и production-сборка прошли после подключения предоставленных данных и AI. После обновления `baseline-browser-mapping` отчёт npm audit по всем зависимостям содержит **0 известных уязвимостей**; это результат конкретного аудита, а не гарантия безопасности. Полный путь с откликом и выбором команды ещё не проверяется: эти функции относятся к следующему этапу.

## Установка в чистой копии

Для независимой проверки создана временная копия без `.git`, `node_modules`, `.next`, `.venv`, SQLite, рабочей папки данных и локальных `.env`. В неё перенесены актуальные на начало проверки lock-файл и исправления подключения компонентов редактора. Зависимости рабочей копии не переиспользуются; загрузочный кэш пакетных менеджеров допустим.

`python3 scripts/setup.py` создал новое виртуальное окружение, установил backend-зависимости, выполнил `pip check` без конфликтов и успешно установил 676 пакетов через `npm ci`. В чистой копии повторно пройдены все 20 API-тестов. `python3 scripts/setup.py --check` также завершился успешно.

`npm --prefix frontend run build` в чистой копии завершился успешно: компиляция, TypeScript и генерация статических страниц выполнены. Для Turbopack потребовался запуск с разрешением на дочерние процессы и служебный локальный порт. После первоначального sandbox-отказа удалена только созданная `.next` временной копии и сборка повторена; исходные серверы и их сборочные файлы не затрагивались. Этот независимый результат относится к снимку первой части до подключения нового набора данных и AI. Зависимости после него не менялись, использован тот же текущий lock-файл; актуальный код с данными и AI дополнительно успешно собран координатором в рабочем проекте.

`python3 scripts/dev.py --check` корректно отменил запуск из-за уже занятых портов 8000 и 5173 (`Address already in use`). Действующие серверы не останавливались. Поэтому этим прогоном проверены установка, инициализация API через TestClient и защита от занятых портов; совместный запуск двух новых сервисов на этих портах не заявляется проверенным.

Проверка выявила неверно заявленный минимум Python 3.10: импорт `datetime.UTC` требует Python 3.11. В инструкции и установщике минимум исправлен на 3.11; проверка установки выполнялась на Python 3.13.9 и Node.js 25.8.0. Сетевой доступ нужен для установки. Первоначальное ограничение DNS внутри sandbox было устранено разрешённым запуском установки с доступом к сети.

## Совместный запуск и остановка

После остановки своих прежних dev-серверов координатор выполнил `python3 scripts/dev.py --production` в рабочем проекте. FastAPI и Next.js запустились; запрос страницы на порту 5173 и `/api/health` через frontend-прокси дали HTTP 200. Все пять официальных оценок сохранились после перезапуска.

Проверены занятые порты: `dev.py --check` корректно отказывает при работающих серверах. В проверку порта добавлен `SO_REUSEADDR`, чтобы состояние TCP TIME_WAIT без активного слушателя не объявлялось занятым сервером.

Реальный Ctrl-C привёл к завершению обоих сервисов и коду выхода 130. После остановки `dev.py --check` подтвердил свободные порты; повторный production-запуск снова успешно поднял оба сервиса. Это проверка актуального совместного запуска в рабочем проекте; отдельная чистая копия использовалась для независимой установки и сборки без остановки исходных серверов.

## Границы безопасности и проверки

`X-Demo-Role` — переключатель локального демонстрационного режима. Любой клиент может передать этот заголовок; он **не является аутентификацией или защитой данных реальных пользователей**. Проверки подтверждают правила локального сценария, а не безопасность многопользовательского сервиса. В демонстрации используются синтетические профили и контакты.

Сервер предназначен для локального запуска на `127.0.0.1`. Настройки CORS не заменяют аутентификацию. В рамках этой части сайт не развёртывается публично.

API-тесты проверяют хранение и обработку текстов как данных. Они не проверяют визуальную отрисовку и не доказывают отсутствие XSS в интерфейсе: рендеринг текста, загрузка, ошибки, пустые состояния и полный пользовательский путь требуют отдельного прогона в браузере.

AI не получает профили студентов; структурированные контакты и заполненные поля обрабатываются приложением. Пользователь может включить лишние сведения в свободное описание. Автоматический детектор или обезличивание персональных данных не реализованы и не заявляются. `.env.example` служит справкой с пустым ключом; приложение не загружает `.env` автоматически, настройки задаются в окружении backend.

Рейтинг оценивает подтверждённую полноту описания. Он не доказывает достоверность сведений бизнеса, доступность данных или реализуемость проекта.

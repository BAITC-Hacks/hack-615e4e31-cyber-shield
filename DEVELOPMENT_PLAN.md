# Исторический план первой части MVP HackAlem

> Этот документ сохраняет план и состояние первой части до реализации откликов, наград и подключения реального AI. Числа тестов, ограничения и команды ниже относятся к тому этапу и не описывают текущую версию. Для сдачи используйте [актуальный README](README.md), [простую инструкцию](docs/QUICKSTART.md) и [подробную инструкцию](docs/RUNBOOK.md). Код, текущие проверки и правила запуска описаны там.

Статус на 23 сентября 2026 года: первая часть расширена предоставленным набором данных и AI-помощником. Полный backend-прогон: 58 тестов пройдены, одно предупреждение зависимости; актуальные lint, typecheck и production-сборка интерфейса успешны. Основные действия и локальный AI-сценарий проверены в браузере; совместный production-запуск, Ctrl-C и повторный запуск также пройдены. Адаптер OpenAI проверен с имитацией HTTP-ответов; платные обращения к реальному API не выполнялись. Полноценные отклики и ручной выбор команды бизнесом ещё не реализованы.

Цель полного MVP — провести слабое описание бизнес-задачи через уточнение, подтверждённую карточку и публикацию до отклика и выбора команды. Ориентир исходного кейса — пять часов; это ограничение хакатона, а не обещание оставшегося времени разработки.

## Что реализовано в первой части

- Локальный интерфейс React 19 / Next.js 16 на `127.0.0.1:5173` и API Python / FastAPI на `127.0.0.1:8000`. Next.js передаёт запросы `/api` в backend.
- SQLite хранит черновики, отдельные опубликованные снимки, тестовые профили студентов, решения по рекомендациям и исходные записи предоставленного набора. Обычный запуск не сбрасывает данные.
- Роли «Бизнесмен» и «Студент» переключаются в демонстрационном интерфейсе. Это не регистрация и не настоящая аутентификация.
- Бизнес создаёт и редактирует карточку в четырёх разделах, видит предварительный рейтинг, сохраняет черновик и явно подтверждает сведения перед публикацией. AI-помощник задаёт вопросы, показывает предложенные поля с источниками и переносит их в редактор только отдельным действием пользователя; сам он не сохраняет и не публикует задачу.
- Каталог показывает опубликованные задачи по убыванию рейтинга; предусмотрены поиск, фильтры темы и готовности. Есть разделы «Мои задачи», «Мои квесты», просмотр карточки и разбивки рейтинга.
- Студент выбирает тестовый профиль и навыки. Рекомендации-квесты требуют оценки от 40 и всех явно указанных навыков задачи; если требований к навыкам нет, используется совпадение интереса с темой или отраслью. Сохранение или пропуск сохраняются в базе.
- Новый стартовый набор взят из `fixtures/hackalem_synthetic_data.json`: пять опубликованных карточек с оценками 20/50/75/90/100 и пять исходных черновиков. Пять команд и пять откликов сохранены в SQLite вместе с другими исходными записями и доступны только для чтения через `/api/demo-data`. Их наличие не означает реализацию отправки отклика или решения бизнеса. В интерфейсе пока используются отдельные пять профилей студентов.
- Идентификаторы источника сохранены, API использует стабильные UUID5. При обновлении существующей базы исходные записи добавляются без удаления старых демонстрационных и пользовательских задач, профилей и решений по квестам.

Сохранение квеста выражает интерес и не назначает исполнителя. Низкий рейтинг не скрывает опубликованную задачу и не запрещает её сохранить из каталога. Рекомендации добавлены в текущую часть по выбранному объёму продукта, но не заменяют обязательные функции полного кейса.

API и модель первой части зафиксированы в [контракте](docs/PART1_CONTRACT.md), результаты проверок и их ограничения — в [отчёте](docs/PART1_VERIFICATION.md). Статус «реализовано в коде» не означает, что интерфейс уже прошёл все пользовательские проверки.

## Команда и области работы

Пользователь принимает продуктовые решения, проверяет удобство и готовит защиту. Координатор согласует работу агентов, соединяет модули и ведёт проверку общей сборки.

| Исполнитель | Текущая область | Критерий завершения |
| --- | --- | --- |
| Агент backend и архитектуры | `backend/app/`, зависимости backend, документация и скрипты запуска | API соответствует контракту, SQLite сохраняет данные, запуск воспроизводим по README |
| Агент интерфейса | `frontend/components/tasks/`: редактор, карточка, панель рейтинга и стили | Поля редактируются, подтверждение явно, видны ошибки и состояние сохранения |
| Агент проверки | `backend/tests/`, отчёт проверки и актуальность плана | Проверены бизнес-правила на временных базах; покрытие и ограничения описаны без завышения готовности |
| Координатор | Общие типы, API-клиент, главный экран, каталог, навыки, квесты, интеграция и браузерная проверка | Пользовательский путь первой части работает в общей сборке |

Контракты и зависимости меняются через координатора. Агенты не редактируют чужие области без согласования. AI-модуль находится в `backend/app/ai.py`, его контракт и ограничения — в `docs/AI.md`. Границы файлов для откликов будут выделены перед следующей частью; агенты-разработчики не являются AI-функцией внутри продукта.

## Правила данных и публикации

Текущие рабочие сущности: поля карточки, задача с ревизией, опубликованный снимок, результат рейтинга, профиль студента и сохранённая/отклонённая рекомендация. Дополнительно `fixture_records` хранит 20 исходных записей четырёх наборов. `/api/demo-data` возвращает исходный набор и карту десяти API-идентификаторов карточек/черновиков; это справочный снимок, не актуальный список решений бизнеса. Контракт фронтенда находится в `frontend/lib/contracts.ts`, серверная валидация — в `backend/app/models.py`.

Создание и любое сохранение правки дают неподтверждённый черновик. Его начисленный рейтинг равен нулю; `previewRating` показывает возможный результат после подтверждения. Подтверждение относится к текущей версии. Публикация требует подтверждённую версию и содержательное название, но не требует минимального рейтинга.

После редактирования ранее опубликованной задачи каталог продолжает показывать прежний снимок. Новый текст и его оценка попадают в каталог только после повторного подтверждения и публикации. Эти переходы проверены через API, в том числе сохранность публичного снимка и изменение позиции после обновления.

Импортированные карточки сохраняют `sourceId`, `sourceDraftId`, отрасль и список подтверждённых полей. Рейтинг импорта учитывает только заполненные подтверждённые поля; API не позволяет клиенту подставить служебное подтверждение или источник при создании. Пользовательская правка сохраняет связь с источником, но снимает подтверждение текущего черновика.

Для следующей части добавляются рабочие операции команд и откликов. Отклик будет доступен на любую опубликованную задачу независимо от баллов и рекомендаций. Принятие одного отклика не должно отклонять остальные автоматически или закрывать задачу: бизнес может выбрать несколько команд либо никого.

## Рейтинг готовности описания

Формула реализована в `backend/app/domain.py`:

| Критерий | Полные баллы | Частичный зачёт |
| --- | --- | --- |
| Контекст и потребность | 20 | Контекст 10 + потребность 10 |
| Данные и материалы | 20 | 20 за заполненное поле |
| Ожидаемый результат | 15 | 15 за заполненное поле |
| Критерии успеха | 15 | 15 за заполненное поле |
| Ограничения | 10 | 10 за заполненное поле |
| Пользователи | 10 | 10 за заполненное поле |
| Связь с бизнесом | 10 | Контакт 5 + формат консультаций и обратной связи 5 |

Деление 5+5 соответствует `scoring_policy` предоставленного набора и заменяет первоначальные 4+3+3. Отдельное поле `feedbackProcess` сохраняется как дополнительное описание без самостоятельных баллов; порядок обратной связи входит в `interactionFormat`.

Пустой текст, пунктуация без содержимого и явные заглушки вроде «уточнить», «неизвестно», `TBD`, `...` баллов не дают. Название компании, длина описания и популярность бизнеса на балл не влияют. Начисление происходит после ручного подтверждения; в редакторе отдельно показана предварительная оценка.

Уровни: 0–39 — нужно уточнить, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Каталог сортируется по убыванию баллов; равные оценки имеют стабильный порядок по идентификатору.

Проверены нулевая и полная оценки, частичный зачёт, суммы разбивки, повторяемость расчёта и перестановка карточек после публикации изменённого рейтинга. Формула оценивает подтверждённую полноту текста. Она не доказывает достоверность утверждений бизнеса, доступность данных или реализуемость проекта.

## Рекомендации-квесты первой части

Это детерминированное сопоставление, а не AI-функция. Квест предлагается только для опубликованной карточки с оценкой от 40. Если навыки явно указаны, все они должны быть в профиле; интерес не обходит отсутствующий обязательный навык. В предоставленных карточках требований к навыкам нет, поэтому они не выдумываются: используется точное совпадение интереса с темой или отраслью, и причина показывается отдельно. Сравнения не зависят от регистра. API возвращает не более трёх рекомендаций.

Решения `saved` и `dismissed` сохраняются для конкретного профиля и исключают повторную выдачу этой рекомендации. Сохранённые задачи доступны в «Моих квестах», включая задачи ниже 40, сохранённые из общего каталога. Решение по рекомендации не меняет карточку и не создаёт отклик или назначение команды. Эти правила проверены интеграционными тестами, включая повторный запуск приложения.

### Зафиксированные проверки и оставшаяся приёмка

1. Актуальный backend: **58 passed, 1 warning**, время 1,33 секунды. Последние `lint`, `typecheck` и production-сборка прошли после подключения набора данных и AI. После обновления `baseline-browser-mapping` отчёт npm audit по всем зависимостям содержит 0 известных уязвимостей; это не является гарантией безопасности приложения.
2. В браузере пройдены создание, подтверждение и публикация слабой карточки, сохранение и пропуск квестов, изменение навыков и сохранение задачи с низким рейтингом. На ширине окна 390 px в проверенном состоянии горизонтального переполнения нет.
3. Локальный AI показал шесть вопросов. Ответы о потребности, данных и результате вошли в предварительную карточку с точными источниками; существующее название сохранилось, неизвестные поля остались пустыми. После явного переноса предварительный рейтинг составил 55; публикация оставалась недоступной до отметки подтверждения человеком.
4. Чистая установка и production-сборка предыдущего снимка выполнены независимо; после этого зависимости не менялись, используется тот же текущий lock-файл. Сам актуальный код дополнительно собран в рабочем проекте. `dev.py --check` корректно отказал при занятых портах без остановки работающих серверов. Дополнительно в рабочем проекте проверены совместный production-запуск, HTTP 200 страницы и API через прокси, сохранение пяти официальных оценок, Ctrl-C с завершением обоих сервисов и кодом 130, свободные порты после остановки и успешный повторный запуск. Совместный запуск выполнялся отдельно от чистой установки.
5. Для полной защиты ещё требуется связать существующий путь с новым откликом и решением бизнеса и пройти его с таймером. Изменение позиции каталога после пересчёта уже доказано API-тестом; этот эффект следует включить в полную браузерную демонстрацию.

### AI-помощник: реализация и пределы проверки

AI реализован в этом репозитории по согласованному контракту. Упомянутый внешний ZIP-модуль не был доступен и не импортировался. Подробные форматы, фактический промпт и тестовые сценарии находятся в [docs/AI.md](docs/AI.md).

Сервер поддерживает OpenAI Responses API и явно обозначенный `local_stub`. Без ключа или при ошибке внешнего сервиса локальная заглушка выбирает вопросы по незаполненным полям и переносит явно адресованные ответы человека. Она не выдаётся за вызов модели или смысловой анализ свободного текста. Внешний режим выбирает вопросы из банка и извлекает полные фрагменты описания в пустые поля.

Предложения содержат источники; существующие поля сохраняются, неизвестные значения остаются пустыми. Сервер проверяет строгий формат, допустимость вопросов и точное совпадение новых цитат с разрешёнными фрагментами исходного текста. Проверка цитат не доказывает правильность выбора поля, истинность исходного текста или отсутствие смысловой ошибки: человек просматривает и редактирует результат.

AI-маршруты не сохраняют, не подтверждают и не публикуют карточки, не начисляют рейтинг и не выбирают команды. Предложения переносятся в редактор отдельным действием. Контакт и заполненные поля обрабатываются приложением, профили студентов не передаются модели. Свободное описание может содержать сведения, введённые пользователем; автоматический детектор или обезличивание персональных данных не реализованы и не заявляются.

Адаптер, источники, ошибки, роль и отсутствие побочных изменений проверены 29 тестами с `httpx.MockTransport`; запросы к реальному OpenAI не выполнялись. Локальный сценарий проверен в браузере с явной отметкой режима. Ключ хранится только в окружении backend. Доступность модели для конкретного аккаунта и качество реальной внешней генерации остаются непроверенными.

### Добавить отклики и выбор бизнеса

1. Подключить пять предоставленных профилей команд к рабочему сценарию: название, интересы, навыки и технологии уже есть в исходных данных. Текущие студенческие профили не объявляются готовой заменой командным операциям.
2. Отклик на опубликованную задачу: команда, идея, план, срок и ссылка на прототип. Низкий рейтинг и отсутствие рекомендации не препятствуют отклику; общего лимита откликов нет.
3. Бизнес просматривает предложения и вручную принимает или отклоняет каждое. Допустимы одна, несколько или ни одной принятой команды; автоматического назначения нет.
4. Подключить пять предоставленных откликов к сценарию и добавить проверки отправки/решений. Само хранение исходных откликов не заменяет полный прогон от описания до принятия.

Баллы студентам за подтверждённый этап упомянуты в шаге 8 кейса, но не раскрыты в обязательных модулях и демонстрации. После основного пути можно добавить одно ручное подтверждение результата с однократным начислением баллов без полноценного трекера.

### Подготовить полную защиту

Один пример проходит AI-уточнение, редактирование, объяснимый рост рейтинга, публикацию, самостоятельный отклик команды и ручное решение бизнеса. Переходы выполняются в приложении. Прогон с таймером должен уложиться в пять минут. Техническая инструкция, AI-материалы, формула, тестовые сценарии и известные ограничения входят в сдачу.

## Регулярное сохранение в GitHub

Репозиторий: https://github.com/BAITC-Hacks/hack-615e4e31-cyber-shield.git. Рабочая ветка: `main`.

Пользователь явно запросил первый commit и push текущих материалов сразу и последующее сохранение новых изменений каждые 40 минут. Под деплоем в этом запросе понимаются только commit и push в GitHub. Развёртывание сайта не входит в эту автоматизацию.

В текущей задаче Codex создана активная автоматизация `github-40`. Она проверяет состояние проекта, сохраняет целостный промежуточный снимок кода и документации и отправляет коммиты в `origin/main`. При отсутствии изменений и неотправленных коммитов новый коммит не создаётся. Незавершённые части и известные проблемы отмечаются в описании промежуточного коммита.

Координатор согласует снимок с работающими агентами, проверяет состав изменений и исключает секреты, зависимости, локальные данные и сборочные артефакты. Удалённая история сохраняется; force push не используется. Ошибка доступа или конфликт сообщаются пользователю. Автоматизация сохраняет уже сделанное и сама по себе не запускает разработку новых функций.

Расписание выполняется локально через Codex, поэтому компьютер должен быть включён, приложение запущено и доступ к GitHub сохранён. Уведомления выдаются об отправке новых изменений или новой проблеме; неизменившееся состояние не порождает повторные сообщения.
